# 条件表达式支持计划书（if_else expression）

## 背景

`if_else` 目前只支持结构化条件 `condition`（`ConditionRule`），其 `condition_value` 是**字面量**，
只能表达「某变量 == true / == 某个固定字符串」。

但实际需求里经常要**两个变量互相比较**，例如抽奖动作要校验「我刚发的评论是否生效」：

```
评论区首条（或前几条）评论的作者 == 我的昵称（self_nickname）
```

`self_nickname` 是运行期变量，无法写进字面量，所以结构化条件做不到。

## 设计

### 1. 参数（`IfElseParams`）

新增 `expression: str | None`，与 `condition` **二选一**（`model_validator` 兜底校验，
两者都给或都不给直接报错）。已有动作全部只传 `condition`，向后兼容。

### 2. 编译（`PipelineBuilder`）

`IF_ELSE` 分支读取 `params.expression` → `IfElseStep.expression`；原 `condition` 逻辑不变。

### 3. 执行（`IfElseStep`）

- 有 `expression` → `safe_evaluate_condition(expression, scope.snapshot())`；
- 否则沿用 `evaluate_rule(condition_rule, ...)`。

`safe_evaluate_condition` 是既有的 AST 白名单求值（`app/services/execution/actions/safe_eval.py`，
**不使用 eval**），白名单含：变量名、字面量、比较（`== != < <= > >= in not in is`）、
布尔/一元/二元运算、list/tuple、dict 下标。因此 `self_nickname in latest_comment_users`
（判断列表成员）与 `a == b`（变量比较）都可用；不支持函数调用，所以不能 `.strip()`。

异常处理与结构化条件一致：求值异常/变量未定义 → 记 warning、走 false 分支（不中断运行）。

### 4. 使用方（`参与B站抽奖` 动作）

第三方评论抽奖循环，发评论后新增校验闸门：

1. `wait .reply-item`（评论区出现条目，`on_error=continue`，输出 `comment_ready`）；
2. `get_text`（`item_selector=.reply-item`，`selector=.sub-user-name`，输出作者名列表
   `latest_comment_users`；用列表而非单条，容忍「置顶评论不是自己」）；
3. `if_else` 表达式 `self_nickname in latest_comment_users`：
   - 真 → 点赞 → 跳空间页 → 关注 → `mark_resource_result` → 每轮结果打印；
   - 假 → 打印「评论未生效」并**不点赞、不标记**（下一轮重试）。

循环体入口 print 用 `input_vars` 把 `latest_comment_users = []`、`latest_comment_users_text = ""`
每轮重置，避免上一轮残留或未定义导致模板解析失败。

## 不做的事

- 不引入 `eval` / 表达式沙箱外能力（仍走 AST 白名单）；
- 不改结构化条件的语义（前端表单继续用 `condition`）；
- 不做「评论内容文本比对」（渲染可能加格式，作者名比对更稳）。

## 验证

- `pytest test/actions/test_if_else_expression.py`：表达式为真/为假时分别进入 True/False 分支；
- 抽奖动作静态校验：`PipelineBuilder.build` 通过，闸门 `if_else` 的 `expression` 正确编译；
- 真实运行需在浏览器上确认评论区作者节点选择器（`.reply-item` / `.sub-user-name`）。
