# 工作流输入变量增量更新计划书（variables_patch）

## 背景

`WorkflowUpdateRequest.variables` 的语义是**整体替换**：

```python
if variables is not None:
    model.variables = variables   # 传了就覆盖整份
```

由此产生过真实故障：前端在「变量契约还没加载完」时提交了空对象 `{}`，后端按替换语义写库，
把用户已配置的 model / key / prompt **全部清空**（2026-10-23 实际发生，已手动恢复）。

前端侧已经加了两道防护（契约未加载不下发 `variables`、加载中禁用保存），但语义本身仍是
「全量替换」——只要有一次请求体不完整，就会丢数据。本次补一个**增量更新**入口。

## 设计

### 1. 请求字段（`WorkflowUpdateRequest`）

```python
variables: dict | None = None          # 既有：整体替换（保持不变）
variables_patch: dict | None = None    # 新增：增量更新
```

- 两者**互斥**：同时传 → 400（语义冲突，避免"想改一个却清了全部"）；
- `variables_patch` 语义：`{name: value}` 逐个覆盖；**值为 `null` 表示删除该键**；
- 未在 patch 中出现的键保持不变。

### 2. 合并（`WorkflowCrudService.update`）

抽出纯函数，便于单测：

```python
def merge_variables_patch(current: dict | None, patch: dict | None) -> dict:
    merged = dict(current or {})
    for key, value in (patch or {}).items():
        if value is None:
            merged.pop(key, None)
        else:
            merged[key] = value
    return merged
```

替换优先级：`variables`（非 None）> `variables_patch`（非空）> 不修改。

### 3. 前端（`WorkflowEditDialog`）

- 保存时提交 `variables_patch`，只包含**与打开时快照不同**的键：
  - 有值 → 新值；
  - 打开时有值、现在清空 → `null`（删除）；
- 契约未加载（`inputVarFields` 为空）→ 两个字段都不下发；
- 无可提交差异时不带 `variables_patch`（不产生空写入）。

### 4. 兼容性

- 存量调用方（其它端、脚本）继续用 `variables` 全量替换，行为不变；
- 两个字段都缺省 = 不修改变量（与现在一致）；
- 历史数据无需迁移。

## 自检清单

- [ ] `variables` 与 `variables_patch` 同时传 → 400，且不改库；
- [ ] patch 只改给出的键，其余保留；
- [ ] patch 中 `null` 删除键；
- [ ] 前端只提交差异键，撤销后不再提交该键；
- [ ] 契约未加载时不提交任何变量字段（防清空）；
- [ ] 单测覆盖合并函数 + 前端差异构造（纯逻辑）。
