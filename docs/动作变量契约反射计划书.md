# 动作变量契约反射计划书

## 背景

工作流步骤通过 `{{变量名}}` 模板消费变量（`Scope.resolve_params`），step 上有
`input_vars: Dict[str, Any]` / `output_vars: list[str]` 两个自由字段，但**没有任何
静态声明**来源说明"这个动作需要哪些变量、产出哪些变量"。前端 `ActionParamsForm.vue`
的输入变量区是纯键值对文本输入，不校验、不补全。目标：动作能反射（自描述）出自己
需要的变量契约，交给工作流配置界面动态渲染。

## 设计

### 1. 变量契约声明（动作自描述）

- 新增 `VariableSpec`（`app/models/execution/action_params.py`）：
  `name / type(string|number|boolean|array|object) / required / description / default`。
- `BaseActionParams` 增加类级契约字段（`ClassVar`，不进 `model_json_schema()`、
  不参与 params 序列化）：
  - `input_variables: ClassVar[list[VariableSpec]]`（该动作消费的变量）
  - `output_variables: ClassVar[list[VariableSpec]]`（该动作产出的变量）
- 内置动作在各自 `XxxParams` 上声明契约（本期仅给典型动作声明，其余走扫描兜底）。

### 2. `{{}}` 模板扫描兜底

复用 `Scope._TEMPLATE_RE` 的正则语义，对 `params_model.model_json_schema()` 所有
string 字段的 description/const/default 做扫描，自动提取变量名，与显式声明合并
（显式声明优先，同名列保留显式的类型/必填信息）。

### 3. 反射出口

- `ActionMetadata` / `ActionMetadataResponse` 增加
  `input_variables / output_variables: list[VariableSpec]`。
- `BuiltinActionType.metadata` 计算契约，`/actions/registered` 自动下发。

### 4. 自定义复合动作契约聚合

- `app/services/execution/variable_contract.py` 的
  `compute_custom_action_variable_contract(steps)`：递归展开 steps（含 loopBranch /
  TrueBranch / FalseBranch / on_error_branch，嵌套自定义动作引用防循环），
  对每个步骤取其动作的 `input_variables` 并集，减去内部自产变量
  （各步骤 `output_vars` 动态赋值名 ∪ 动作声明 `output_variables` 槽位名），
  得到复合动作对外契约。
- **实现调整**：契约在 `/custom-actions/get` 详情接口**读时计算**并随
  `CompositeActionDetailResponse.input_variables / output_variables` 下发，
  不做写时落库——steps 随时可被编辑，读时计算永远新鲜，也避免覆盖用户数据。
  `parameters_schema` 死字段的激活延后到需要持久化契约时再做。

### 5. 前端（Vue3FrontEndDemoExercise）

- 契约合并进 `json_schema` 透传：`ToolboxPanel.vue` 组装树节点、
  `useDebugboxItems.ts` 的 `refreshRegisteredSchemas` 均把
  `input_variables / output_variables` 合入 schema 对象，
  拖拽 / 草稿 / 分支 / schema 刷新全链路自动携带，零新增 prop。
- `ActionParamsForm.vue`：输入变量区按 `jsonSchema.input_variables`
  渲染契约绑定行（变量名 + 类型 + 必填标 + 值输入，悬停显示说明），
  必填未赋值给校验提示；未声明的动作回退现有键值对模式。
- 输出变量区展示 `output_variables` 产出槽位提示，便于给 `output_vars` 起名。
- **后续迭代**：变量引用可搜索下拉（数据源为前序步骤累计 `output_vars`
  + 复合动作对外契约 + 触发变量）。

## 不做的事

- 不改执行链路（`Scope` / `engine`）运行时语义；strict 解析行为保持不变。
- 内置动作禁止业务专属逻辑的规则不变：变量契约是参数模型的自描述元数据，属通用机制。
- 本期不实现"保存工作流时预校验变量来源"（后续迭代）。

## 验证

- 后端：uv 运行 pytest（`actions` 相关单测 + 新增契约单测）；`/actions/registered`
  实际响应含 `input_variables`。
- 前端：`vue-tsc` 类型检查通过；DebugBox 拖入带契约的动作能看到变量绑定行。
