# 循环名称与运行消息明细计划书（loop name + SSE 参数展示）

## 背景

批量工作流（如「参与B站抽奖」）的主体是「循环遍历数据列表 → 循环体内若干基础操作」。
运行时的可观测性有两个缺口：

1. **循环没有名称**。`LoopParams` 只有来源 / 计数 / 变量名 / 参数映射，没有任何
   「这个循环在干什么」的描述。工作流里出现多个循环（尤其是嵌套循环）时：
   - SSE 运行消息只能显示 `循环「loop」`（`action_id` 兜底）；
   - 进度条只能显示 `第 i/N 轮 · 循环「loop」`；
   - 「快速定位轮次」下拉里全是 `第 ? 轮 · 循环`，分不清是哪一层。
2. **基础操作的执行参数不可见**。运行消息的 `detail` 只包含动作返回数据
   （`ActionResult.data`）与过程日志（`ActionResult.logs`），看不到「这一步到底
   用什么参数跑的」。轮次失败时无法直接从消息栏判断是选择器写错还是变量没解析到，
   必须再去翻操作日志（`ActionLogRecord.params`）。

## 设计

### 1. 循环名称（`LoopParams.name`）

新增可选字段：

```python
name: str | None = Field(
    default=None,
    max_length=200,
    description="循环显示名称（支持 {{变量}} 模板，如 '处理 {{loop_item.title}}'），用于运行消息 / 进度中标识本循环在做什么",
)
```

- 纯静态文本（如「遍历动态列表」）直接展示；
- 含 `{{var}}` 模板时**每轮按当前作用域解析**（此时 `loop_item` / `loop_index`
  已就绪），例如「处理 {{loop_item.title}}」第 3 轮展示「处理 某某的动态」；
- 解析用 `Scope.resolve_text`（非严格）：变量缺失时保留 `{{var}}` 字面量，
  **绝不让名称解析失败影响循环执行**（名称只是展示）；
- 未设置时行为与现在完全一致（回落 `action_id` = `loop`），存量动作 JSON 零改动。

### 2. 编译与执行（`pipeline.py`）

- `PipelineBuilder.build` 的 LOOP 分支读取 `params.name` → `LoopStep.name`；
- `LoopStep` 新增 `name: str = ""` 与 `_resolve_loop_name(scope)`：
  非严格解析模板；结果为空或仍含 `{{`（未解析）时回落 `action_id`；
- `_report_iteration` 把解析后的名称传给 `reporter.loop_iteration(name=...)`，
  `loop_finished` 经 `LoopLayer.name` 自动带上（无需改上报器签名）；
- `StepNode.display_name(scope)`：顶层步骤开始/结束消息与 `current_step_name`
  的显示名。`LoopStep` 覆写为解析后的循环名称（含未解析模板时回落 `action_id`），
  其他步骤仍是 `action_id`。

### 3. 基础操作参数进运行消息（`workflow_progress.py`）

`build_step_detail(result)` 的 detail 由「返回数据 + 过程日志」扩充为
「**执行参数 + 返回数据 + 过程日志**」：

- 参数取 `result.replaced_params`（`engine._run_action_core` 落的是**模板替换后**
  的实际参数，正是「这一步用什么跑的」）；
- 剔除嵌套子步骤字段（`steps` / `loopBranch` / `TrueBranch` / `FalseBranch` /
  `branches`）：复合 / 循环 / 分支动作的整棵子树铺开没有意义，且会把消息撑爆；
- 敏感字段（`llm_api_key` / `token` 等）复用 `action_logger._redact_sensitive`
  脱敏后再进 SSE——虽然 detail 只走 SSE 不落库，也不该把密钥广播出去；
- 仍受 `workflow_run_log_detail_max_length` 结构裁剪约束，默认不裁（0）。

前端 `WorkflowRunMessageItem` 已有 `detail` 折叠/展开交互（首行摘要 + 点击展开），
参数行成为 detail 首行，天然复用现有 UI，**不需要新增 SSE 字段、不需要重新生成 SDK**。

## 不做的事

- 不给 `if_else` / `parallel` 加名称（本次只做 loop；需要时按同一模式扩展）；
- 不改 SSE 事件结构（不加字段），避免前端 SDK 重新生成；
- 不改动既有动作 JSON / DB（name 默认空，行为完全向后兼容）；
- 不在 `actions/**` 内置动作里写任何站点 / 业务逻辑（名称解析是通用机制）。

    五种形态的 `loop_iteration` 上报名称；
  - 顶层步骤 `step_started` 显示名用解析后的循环名称；
  - `PipelineBuilder.build` 读取 `params.name`；不传时 `name=''`（向后兼容）；
  - 存量抽奖动作 JSON 不传 name，静态校验照旧通过；
  - `build_step_detail` 首行为「参数:」行、剔除 `steps`/`loopBranch`/`TrueBranch`/
    `FalseBranch`、`llm_api_key` 脱敏为 `***`、无参数时维持旧形态。
- 前端 `npx vitest run tests/unit/loopNameConfig.spec.ts`（5 用例全过）：
