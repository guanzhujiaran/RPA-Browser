# 前端需求：浏览器真实版本选择与校验

> 关联后端计划书：`docs/浏览器真实版本与模拟版本一致性计划书.md`
> 状态：SDK 已重新生成（2026-11-26），前端已按本需求接入（见 §3/§4）

## 1. 背景

浏览器版本拆成两个字段：

| 字段 | 含义 | 来源 |
|---|---|---|
| `fingerprint_real_version` | **真实版本**：实际启动的 chromium 二进制版本 | 服务端清单（`browser_exec_info.json`），**只能选，不能手输** |
| `fingerprint_brand_version` | **模拟版本**：下发给浏览器的报告版本 | 由真实版本派生，**与真实版本恒等** |

后端已经做了白名单校验：真实版本不在清单内、或真实/模拟主版本冲突，都会返回 400。
前端必须与之对齐，避免用户拼出非法组合。

## 2. 新增接口

`POST /api/v1/rpa/browser/list_exec_versions`（无入参，无需登录）

响应 `data` 为数组，每项：

```ts
interface BrowserExecVersionInfo {
  full_version: string   // 真实版本，唯一可选值，如 "150.0.7871.186"
  major_version: string  // 主版本，如 "150"
  browser_ua: string     // 该版本对应的 UA
  exec_name: string      // AppImage 文件名
  is_installed: boolean  // 二进制是否已落盘
}
```

## 3. 表单改造（`src/views/rpa-browser/FingerprintCreateEdit.vue`）

1. 页面挂载时调用上面的接口，把结果存到 `availableVersions`；失败时给出提示并禁用版本选择。
2. 「平台信息」卡片里的「浏览器版本」一行改成两个字段：
   - **真实版本**（新）：`el-select`，选项来自接口，
     展示文案 `full_version`，`is_installed === false` 时追加「（未安装）」并仍可选（后端会在启动时解包/下载）；
   - **模拟版本**（原 `fingerprint_brand_version`）：可编辑的四段号输入框，
     默认跟随真实版本；**允许在同一主版本内改 patch**（如 150.0.7871.186 → 150.0.7871.124），
     主版本必须与真实版本一致，跨主版本由前端提示 + 后端 400 双重拦截。
3. 「随机生成」回填时：除了原有字段，还要回填 `fingerprint_real_version`，
   并让模拟版本跟着它刷新。
4. 提交前前端校验（与后端同规则，双保险）：
   - 真实版本必须非空且在 `availableVersions` 的 `full_version` 里；
   - 模拟版本为非空四段号（`x.y.z.w`），且主版本等于真实版本；空值时自动补成真实版本。
5. 提交体：`fingerprint_real_version` + `fingerprint_brand_version` 一起传。

> 注意：`el-form` 目前没有绑定 `:model` / `:rules`，改造时把表单校验补上，
> 至少对「真实版本」加 `required` 规则。

## 4. 展示改造

| 位置 | 改法 |
|---|---|
| `src/views/rpa-browser/BrowserDetail.vue` | 「浏览器版本」拆成「模拟版本 / 真实版本」两项；同主版本 patch 不同 → 中性标签「同主版本自定义 patch」，主版本不同 → 红色「主版本与真实版本不一致」 |
| `src/views/rpa-browser/BrowserFingerprintList.vue` | 卡片展示 `真实版本`（主）/ `模拟版本`（次），为空显示 `-` |
| `src/models/rpa_browser/fingerprint.ts` | 类型补 `fingerprint_real_version: string \| null` |
| 浏览器会话信息（`BrowserInfoResponse`） | 新增 `real_version`，可与 `version`（模拟版本）并排展示 |
| GPU 厂商 / 渲染器（表单与指纹详情） | 标注「仅对 Chrome 143 及以下内核生效」；真实版本 ≥144 时提示「已移除该开关，实际 GPU 由指纹种子决定」（字段保留可编辑） |

`real_version`）已随重新生成的 hey-api SDK 落地，前端消费点已接入：

## 6. 验收

- [ ] 下拉只出现清单里的 5 个版本，无法手输其他版本；
- [ ] 改真实版本 → 模拟版本自动跟随，UA 相应变化（可对比会话信息里的 `user_agent`）；
- [ ] 模拟版本改同主版本其它 patch → 可保存，页面读到的 `uaFullVersion` 为新 patch；
- [ ] 模拟版本改成别的主版本 → 前端提示、后端 400；
- [ ] 用浏览器开发者工具篡改提交体传一个清单外版本 → 后端返回 400 且提示可选值；
- [ ] 历史指纹（无真实版本）打开时能正常显示，选择真实版本后可保存；
- [ ] 列表 / 详情页同时展示真实版本与模拟版本。
