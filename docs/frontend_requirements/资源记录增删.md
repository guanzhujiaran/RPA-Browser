# 已处理资源记录：手工新增 / 删除

> 对应后端：`/api/v1/rpa/browser/control/workflows/resources/create`、`.../delete`
> 前端落点：`Vue3FrontEndDemoExercise` → `src/views/rpa-browser/WorkflowResourceRecordView.vue`
> + `src/components/rpa-browser/WorkflowResourceRecordTable.vue`
> 封装层：`src/api/browser/workflow_resource_api.ts`

## 1. 背景

「已处理资源记录」（`WorkflowResourceRecord`）是取数去重的数据源：`status in (success, skipped)`
的资源会被 `fetch_external_data` 剔除，不再参与后续运行。历史上因为参与判定条件偏弱
（如「已点赞」被当成「已参与」），一批**实际没参与**的动态被写成了终态记录，导致后续运行
取数为 0 条、循环 0 轮执行。

后端已提供接口，前端需要给出可视化入口：**能加、能删**，并且删除前能预览影响面。

## 2. 接口契约

### 2.1 新增 / 更新（upsert）

`POST /workflows/resources/create`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `workflow_id` | int | 是 | 工作流ID |
| `resource_type` | str(≤64) | 是 | 如 `bili_lottery_others`，需与取数去重的类型一致 |
| `resource_id` | str(≤128) | 是 | 业务主键（动态 dynId / 预约 sid） |
| `browser_id` | int? | 否 | 不传=工作流配置的浏览器（去重按浏览器隔离） |
| `status` | str? | 否 | `success` / `skipped` / `failed`，不传=success |
| `fail_reason` | str? | 否 | 备注/跳过原因；`success` 时不保存 |
| `extra` | object? | 否 | 附加快照 |

返回：单条记录（结构同列表项 `WorkflowResourceRecordItemResponse`）。

语义：唯一键（工作流 + 浏览器 + 类型 + 业务主键）已存在时**更新状态并累加 `process_count`**，
所以这个接口同时是「新增」和「改状态」：把误记的项改成 `failed` 即可让它重新参与取数。

### 2.2 删除

`POST /workflows/resources/delete`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `workflow_id` | int | 是 | 工作流ID |
| `ids` | int[]? | 否 | 记录主键（列表页勾选） |
| `browser_id` | int? | 否 | 按浏览器过滤 |
| `resource_type` | str? | 否 | 按资源类型过滤 |
| `status` | str? | 否 | 按状态过滤（如只清 `success`） |
| `resource_id` | str? | 否 | 业务主键**精确**匹配（与列表页模糊搜索不同） |
| `run_id` | str? | 否 | 按所属运行清理（清理某一轮的误记） |
| `dry_run` | bool | 否 | `true`=只统计将删除的条数，不实际删除 |

返回：`{ deleted: int, dry_run: bool }`。

**服务端强制约束**：除 `workflow_id` 外至少要给一个条件，否则返回 400，不允许一键清空整个
工作流的去重记录。

## 3. 交互要求

### 3.1 表格页（`WorkflowResourceRecordTable.vue`）

1. 工具栏新增两个按钮：
   - **新增记录**（主按钮，`el-button type="primary"`，class `resource-record__create-btn`）；
   - **删除所选**（默认按钮，危险色，`resource-record__batch-delete-btn`，未勾选时禁用，
     旁边显示已选条数）。
2. 表格首列加 `el-table-column type="selection"`；行操作列加「删除」按钮。
3. 删除确认流程（**所有删除都必须先 dry_run**）：
   - 点击删除 → 先调 `delete(..., dry_run=true)` 拿到 `deleted`；
   - 弹 `ElMessageBox.confirm`：`将删除 N 条已处理记录，删除后这些资源会在下次运行时重新被抓取，确认删除？`；
   - 用户确认后再调 `dry_run=false`，成功后 `ElMessage.success('已删除 N 条')` 并刷新列表。
4. 记录行增加「状态」筛选已有；新增/删除后保持当前筛选条件不变。

### 3.2 新增弹窗（`resource-record__create-dialog`）

字段与校验：

- `resource_type`：`el-select`，选项取当前工作流已出现过的资源类型（从列表去重得到），
  允许自定义输入（`allow-create`），必填；
- `resource_id`：`el-input`，必填，去空格；
- `browser_id`：`el-select`，选项为工作流的浏览器列表，默认取工作流配置，可留空=默认；
- `status`：`el-radio-group`：`success`（已处理，参与去重）/ `skipped`（终态跳过）/
  `failed`（失败，下次重试），默认 `success`；
- `fail_reason`：`el-input`，`status != success` 时显示，占位「如：已点赞并不等于已参与，需重做」。

提交后关闭弹窗并刷新列表（提示「已写入，若为已存在记录则状态已更新、处理次数 +1」）。

### 3.3 按运行清理（可选但建议）

在运行记录详情页（`run_id` 已知处）加一个「清理本轮资源记录」入口：

- 点击 → `delete({ workflow_id, run_id, dry_run: true })` 得到条数；
- 确认文案：`将删除本轮运行写入的 N 条资源记录，这些资源下次会被重新抓取，确认删除？`；
- 确认 → `dry_run=false` → 提示条数。

场景：判定逻辑修复后，清理某几轮被误记的终态，让资源重新参与抽奖。

## 4. UI 规范（项目约定）

- 全部使用 Tailwind 原子类，禁止 `<style>` 块与 `:style`；
- 颜色/尺寸只用 `theme.css` 里的语义化 class（如 `bg-primary`、`text-info-light-3`）；
- 使用 Element Plus 组件（`el-button` / `el-dialog` / `el-form` / `el-table`），尺寸用
  `default` / `large`，禁用 `small`；
- 业务元素带语义化 class（`resource-record__xxx`），不要只用纯样式类作为唯一标识。
