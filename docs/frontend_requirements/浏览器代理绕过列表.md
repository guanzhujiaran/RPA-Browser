# 浏览器代理绕过列表（proxy_bypass）

> 对应后端：`POST /api/v1/rpa/browser/upsert_fingerprint`、`/read_fingerprint`、`/list_fingerprint`
> 前端落点：浏览器指纹编辑表单（与「代理服务器 `proxy_server`」同一区块）
> 后端模型：`RPA-Browser/app/models/runtime/api.py` → `BrowserFingerprintEditableParams`、
> `app/models/core/browser/fingerprint.py` → `BaseFingerprintBrowserInitParams.proxy_bypass`

## 1. 背景

浏览器统一走代理（`proxy_server`）后，某些站点反而不能走代理：内网服务、本机调试端口、
以及只对国内直连放行的站点（走代理会 403 / 风控）。Chromium 原生支持「代理绕过列表」
（`--proxy-bypass-list`），后端已把它接成**每浏览器可配**的字段 `proxy_bypass`：

- 命中规则的主机 → 直连；
- 未命中 → 走该浏览器的代理；
- 该浏览器没配代理（直连）时，这个字段无意义，后端会直接忽略。

服务端还有一个环境变量 `BROWSER_PROXY_BYPASS` 作为兜底：浏览器自己没配 `proxy_bypass` 时用它。
这个值**不会**下发给前端、也不会写进数据库（随部署环境变化），前端不要读取或回显它。

## 2. 接口契约

### 2.1 写入（upsert / 更新）

`POST /upsert_fingerprint`（更新已有浏览器时必须带 `browser_id`）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `browser_id` | str? | 否 | 不传=新建浏览器，传=更新该浏览器 |
| `proxy_server` | str? | 否 | 代理地址，`host:port` 或 `user:pass@host:port` |
| `proxy_bypass` | str? | 否 | **新增**。绕过列表，逗号或分号分隔；空/不传 = 不下发（用服务端兜底） |

语义：

- `proxy_bypass` 只做**归一化**（分号/空格/换行 → 逗号、去重、去首尾空白），不做业务校验；
- 传入 `""` / 全空格 = 「未提供」，按 `exclude_none` 语义**不覆盖**库里已有的值；
- 想清空已配置的绕过列表 → 传 `null` 且不要传 `""`（前端表单「清空并保存」时需显式发 `null`，
  或者在表单侧统一把「用户清空」映射为 `null`）。

### 2.2 校验（前端在提交前做，后端也会做）

后端遇到下面情况返回 400（`ValidationError`），提示文案直接可用：

| 输入 | 结果 | 说明 |
|---|---|---|
| `*.bilibili.com,127.0.0.1` | ✅ | 逗号分隔 |
| `*.bilibili.com;127.0.0.1` | ✅ | 分号也接受，落库前转逗号 |
| `.bilibili.com` | ✅ | 等价于 `*.bilibili.com`（driver 自动补 `*`） |
| `https://bilibili.com` | ❌ | 不能带协议前缀，**只能写主机名/IP** |
| `bilibili.com/video` | ❌ | 不能带路径 |

前端约束：

- 输入框不做自动补 `*`，只做「去空格 + 分号转逗号」的轻度清洗，避免和用户输入的语义打架；
- 含 `://` 时输入框下方红字提示：「只能填域名或 IP，不要带 http://」。

### 2.3 读取

`POST /read_fingerprint`、`/list_fingerprint` 的响应体已包含 `proxy_bypass`（`string | null`），
列表项与详情页直接回显即可。

## 3. UI 需求

### 3.1 编辑表单

- 位置：指纹/环境配置区块，「代理服务器」输入框**正下方**；
- 控件：`el-input`（`type="textarea"` 或普通输入框均可，单行足够，建议 `:rows="2"` 支持多行粘贴）；
- 标签：`代理绕过`；`placeholder`：`*.bilibili.com,127.0.0.1`；
- 帮助文案（表单项底部灰色小字）：
  > 命中的域名/IP 不走代理，逗号分隔；只支持域名或 IP，不能带 http 前缀。
  > 留空则使用服务端默认配置。
- 依赖关系：`proxy_server` 为空时该输入框**禁用**（灰显），提示「该浏览器未配置代理，绕过列表不生效」；
  否则用户会误以为直连配置能靠它生效。
- 保存：与表单其他字段一起走 `upsert_fingerprint`。

### 3.2 列表 / 卡片展示

- 已配置 `proxy_bypass` 的浏览器，在代理信息处追加一枚标签：`绕过 N 条`（N = 逗号分隔后的规则数），
  `el-tooltip` 悬浮展示完整规则；
- 未配置（`null`）不显示任何标签，**不要**显示「跟随服务端」，因为该值前端拿不到。

### 3.3 交互细节

- 用户粘贴 `a.com; b.com;\nc.com` 时，提交前统一转成 `a.com,b.com,c.com`；
- 提交失败（400）时把后端 message 原样展示在输入框下方，不要覆盖用户已输入内容。

## 4. 验收标准

1. 新建浏览器时填写 `proxy_bypass`，保存后 `read_fingerprint` 能读到同样的值（分号已转逗号）；
2. 该浏览器启动后，Chromium 命令行里出现 `--proxy-bypass-list=<规则用分号连接>`，
   且 `*.bilibili.com` 的请求在 `chrome://net-internals/#proxy` 里走 DIRECT；
3. 只配 `proxy_bypass` 不配 `proxy_server` 时，浏览器正常启动（不报 proxy 配置错误），且该字段被忽略；
4. `proxy_server` 为空时表单里 `proxy_bypass` 置灰不可编辑；
5. 清除绕过列表后，`read_fingerprint` 返回 `null`（不是空字符串）。
