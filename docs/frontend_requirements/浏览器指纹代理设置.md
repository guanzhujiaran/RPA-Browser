# 浏览器指纹：代理设置（三选一）

## 1. 背景

同一出口 IP 被多个账号共用时，站点会按 IP 维度风控（验证码、登录态互踢、限流直至封禁），
指纹再逼真也补救不了。项目里同时存在两种代理来源：

- **服务端默认代理**（`settings.default_proxy_server`，环境变量）：dev 环境指向
  `go-proxy-ipv6-pool-auto` 的 HTTP 入口（宿主机 `3128`），即「IPv6 代理池」；
- **浏览器指纹自己的 `proxy_server`**：用户为该浏览器单独配置的代理。

## 2. 三种模式

| 模式 | 落库的 `proxy_server` | 启动时实际行为 |
|---|---|---|
| `pool`（IPv6 代理池） | 字面量 `"pool"` | 回退 `settings.default_proxy_server`；未配置默认代理则直连 |
| `none`（不使用代理） | 字面量 `"none"` | **直连，且不回退默认代理** |
| `custom`（自定义代理） | `host:port`（可选 `user:pass@host:port`） | 使用该代理 |

**池模式为什么也不能用空串**：入参模型会把空串归一成 `None`，更新接口再按「未提供」
跳过 —— 用户从自定义代理切回池时旧代理清不掉，页面显示池、实际仍走旧代理。
显式 `"pool"` 能落库覆盖，解析阶段与空值同义（都回退默认代理），历史空值行为不变。

`"none"` 是显式直连标记（后端 `DIRECT_PROXY_SERVER`）：

- 空值语义是「未配置 → 回退默认代理」，与「明确不用代理」必须区分，
  否则界面显示直连、实际仍走池，是静默的行为不一致；
- `resolve_browser_proxy_server()` 先判断 `"none"` 并直接返回 `None`，不再回退；
- 指纹入参校验（`BrowserFingerprintUpsertParams.validate_proxy_server`）对 `"none"`
  直接放行，不走 `host:port` 格式校验。

## 3. 前端交互

`src/views/rpa-browser/FingerprintCreateEdit.vue`：

- 「代理设置」用 `el-radio-button` 三选一：**IPv6 代理池 / 不使用代理 / 自定义代理**；
- 选「自定义代理」才显示地址输入框，值单独存 `proxyCustomValue`，
  来回切模式不会丢已填内容；
- 「代理绕过」只在自定义模式可编辑；切到池 / 直连时保存会清空绕过列表
  （池与直连不使用绕过规则）；
- 保存时按模式映射 `formData.proxy_server`：池 → `'pool'`，直连 → `'none'`，自定义 → 输入值；
- 回显用 `resolveProxyMode()` 反解，空值 / `pool` → 池、`none` → 直连、其它 → 自定义。

展示（列表详情弹窗、详情页）统一用 `src/utils/rpa/proxy.ts` 的 `formatProxyServer()`：

```
IPv6 代理池（服务端默认）
不使用代理（直连）
1.2.3.4:8080
```

| 位置 | 内容 |

| `app/utils/http/proxy_utils.py` | `DIRECT_PROXY_SERVER` / `is_direct_proxy()`；`resolve_browser_proxy_server()` 识别显式直连 |

| `src/views/rpa-browser/BrowserDetail.vue` | 详情页描述项展示 |
| `app/services/RPA_browser/fingerprint/browser_fingerprint_service.py` | 修复编辑接口 500：`fingerprint_int` 单独映射到 `fingerprint` |

> 顺带修复：编辑指纹时 `fingerprint_int` 曾被直接 `setattr` 到 `UserBrowserInfo`，
> 抛 `"UserBrowserInfo" object has no field "fingerprint_int"` —— 只要请求里带种子，
> 编辑任意字段都会 500。现在从 `update_data` 中弹出并映射到落库字段 `fingerprint`，
> 编辑时改种子也会真正生效。

## 5. 验收清单

- [ ] 新建指纹选「IPv6 代理池」→ 落库 `proxy_server='pool'`，启动日志显示默认代理（或直连）；
- [ ] 选「不使用代理」→ 落库 `"none"`，启动日志显示「未配置（直连）」，即使服务端配了默认代理也不走；
- [ ] 选「自定义代理」填 `127.0.0.1:7890` → 落库该值，启动走该代理；
- [ ] 编辑一个原有自定义代理的指纹 → 默认回显「自定义代理」+ 原地址；切到池保存后旧代理被清空；
- [ ] 池 / 直连模式下「代理绕过」输入框禁用，保存后 `proxy_bypass` 为空；
- [ ] 列表详情与详情页对三种模式的展示文案正确。
