# 动作分类与检索规格（前端需求）

> 适用组件：`src/components/rpa-browser/ToolboxPanel.vue`（动作工具箱，「基础操作」tab）、
> `src/components/rpa-browser/ActionPickerDialog.vue`（工作流选动作弹窗）
> 新增模块：`src/utils/rpa/actionCategory.ts`（分类映射 + 打分检索 + 分组树，纯函数）
> 关联后端：`POST /api/v1/rpa/browser/control/actions/registered`（31 个内置动作元数据，无 category 字段）
> 关联后端模型：`app/services/execution/actions/all_actions.py`、`app/models/execution/builtin_action_types.py`

---

## 1. 背景与问题

后端内置动作已从 12 个增长到 **31 个**（含 `press` / `wait_for_response` / `element_state` /
`select_option` / `wait_for_url`）。前端当前把「基础操作」渲染成一棵**只有一层**的 `el-tree-v2`
（每个节点 `children: []`，见 `ToolboxPanel.vue` 的 `filteredRegistered`），`ActionPickerDialog`
也是平铺列表。

结果：

1. 31 项平铺，滚动找动作成本高，且看不出「这些动作是干哪一类事的」；
2. 搜索只做 `name.toLowerCase().includes(q)`，中文名、action_id、描述、分类名都不参与匹配；
3. 动作标题表 `actionTitleMap`（`ToolboxPanel.vue`）与图标表 `ACTION_TYPE_ICONS`
   （`src/utils/rpa/actionTypeIcon.ts`）**覆盖不全**，新增动作会回落成原始 id / 问号图标。

本文档定义：**分类归属算法、检索打分算法、分组树构建算法**，以及两个组件的交互规格。

---

## 2. 分类方案（7 类，覆盖全部 31 个动作）

| # | 分类 id | 显示名 | 分类语义 | 动作 |
|---|---|---|---|---|
| 1 | `interaction` | 页面交互 | 直接作用于页面元素（点击 / 输入 / 悬停 / 选择） | `click` `input` `press` `hover` `scroll` `select_option` |
| 2 | `navigation` | 导航与页面 | 切换页面、管理标签页、等 URL 变化 | `navigate` `new_page` `open_page` `close_page` `wait_for_url` |
| 3 | `probe` | 等待与提取 | 等条件成立、读页面上的值 | `wait` `wait_for_response` `get_text` `get_window` `element_state` |
| 4 | `data` | 数据处理 | 纯内存计算与外部取数，不碰页面 | `print` `random_pick` `pick_line` `shuffle_list` `sort_list` `fetch_external_data` |
| 5 | `control` | 流程控制 | 控制步骤执行结构 | `loop` `if_else` `parallel` `composite` |
| 6 | `business` | 业务与通知 | 站点业务语义、结果落库、对外通知 | `bili_reserve` `mark_resource_result` `notify` |
| 7 | `media` | 媒体与 AI | 产出产物或依赖模型的动作 | `screenshot` `llm` |

约束：

- 分类**只在前端**维护，**不改后端接口**：`ActionMetadataResponse` 不新增字段，
  避免动 MCP schema、`scripts/check_action_consistency.py` 与已发布 SDK；
- 分类是「导航辅助」，不是权限/执行语义，**任何分类错误都不得影响动作能否执行**；
- `composite` 在「基础操作」tab 已被过滤（`ToolboxPanel.vue` `loadRegistered`），
  分类表仍保留它，供其它入口（如 ActionPicker）使用。

## 3. 分类归属算法

```ts
type ActionCategoryId =
  | 'interaction' | 'navigation' | 'probe' | 'data' | 'control' | 'business' | 'media'

resolveActionCategory(actionId: string): ActionCategoryId
```

规则（按优先级）：

1. **静态表命中**：`ACTION_CATEGORY_MAP` 精确匹配 `action_id` → 直接返回；
2. **前缀/关键词兜底**（仅用于表里未收录的新动作，避免新动作落进「未分类」）：
   - `wait*` → `probe`
   - `get*` → `probe`
   - `*_list` / `random*` / `print` / `fetch*` → `data`
   - `loop` / `if*` / `parallel` / `composite` → `control`
   - `*_page` / `navigate` / `*url*` → `navigation`
   - `screenshot` / `llm` → `media`
   - `mark*` / `notify` / `bili*` → `business`
3. **最终兜底** → `interaction`（保证任意 id 都有分类，不出现空分组）。

完备性保障：`ACTION_CATEGORY_MAP` 用 `Record<BuiltinActionId, ActionCategoryId>` 声明，
`BuiltinActionId` 是 31 个内置 `action_id` 的联合类型。**后端新增动作时 TS 会编译报错**，
强制开发者补分类，而不是静默落进兜底分支。

## 4. 检索打分算法

用于分类内排序与跨分类筛选。输入一条动作元数据（`action_id` / `name` / `description`）
与查询串 `q`，输出 0~N 的分数；**分数为 0 视为不命中**。

查询串归一化：`q.trim().toLowerCase()`；空串直接跳过打分（全部命中，按默认顺序）。
被匹配字段同样 `toLowerCase()`。

| 命中位置 | 分值 | 说明 |
|---|---|---|
| 名称完全相等 | 100 | 输入「点击」精确命中 |
| 名称前缀 | 70 | 输入「点」 |
| 名称子串 | 45 | 输入「击」 |
| `action_id` 完全相等 | 90 | 输入 `click` |
| `action_id` 前缀 | 55 | 输入 `wa` → wait / wait_for_url / wait_for_response |
| `action_id` 子串 | 30 | 输入 `resp` |
| 分类显示名前缀/子串 | 15 | 输入「导航」命中整类 |
| 描述子串 | 10 | 输入「键盘」 |

加成项（可叠加，合计上限 +30）：

| 来源 | 加成 |
|---|---|
| 最近使用过（`recentIds` 前 5 个） | +20，按名次递减（20/16/12/8/4） |
| 累计使用次数 ≥1 | `+min(10, Math.log2(count + 1) * 3)` |

同分排序（稳定）：分类固定顺序 → 最近使用名次 → 使用次数降序 → `name` 的 `localeCompare('zh')`。

> 不引入拼音依赖：中文输入走「名称子串」，英文/拼音走 `action_id` 前缀，
> 避免为搜索增加一个 npm 包与新维护面。

## 5. 分组树构建算法

```ts
buildActionTree(actions: ActionMeta[], query: string): ActionTreeGroup[]
```

1. 逐个动作 `resolveActionCategory` 得到分类；
2. `query` 非空时计算分数，**分数为 0 直接丢弃**；
3. 按分类聚合 → 分类内按第 4 节顺序排序；
4. 分类节点按「命中数量降序 → 固定顺序」排序；
5. **空分类不渲染**（查询时自然收敛，无结果时给空态提示）；
6. `query` 非空时所有分类默认展开，命中分类高亮，节点右侧显示命中数量。

「常用」虚拟分类（仅 `ToolboxPanel`）：当 `recentIds` 非空时，在最前面插入
`categoryId = '__recent__'` 的分组，包含最近使用过的动作（最多 5 个，按使用时间倒序），
该分组在搜索时同样参与打分过滤。

## 6. 交互规格

### 6.1 ToolboxPanel「基础操作」tab

- 树结构：一层分类节点 + 二层动作叶子，分类节点显示「分类名 + 动作数」，可折叠；
- 默认展开：`interaction` / `navigation` 两类（最常用），其余折叠；
- 搜索框（现有 `el-autocomplete`）：保留联想，但联想数据源改为**分类树叶子节点的扁平列表**，
  命中项下拉展示「分类 / 动作名」；
- 拖拽：分类节点**不可拖拽**（`draggable: false`、`allow-drop` 返回 false），
  叶子节点行为与现状一致；
- 叶子节点仍携带 `json_schema`，拖入画布后行为不变（`DroppedItem` 结构不改）。

### 6.2 ActionPickerDialog（自定义动作选择器）—— 本期不改

`ActionPickerDialog.vue` 列的是**用户保存的自定义动作**（`/custom-actions/list`，私有/公开分段 + tags 过滤），
不是 31 个内置动作，因此**不套用本文件的分类体系**：自定义动作的组织维度是用户自己的 `tags`，
把内置分类强加进去会让两套体系互相污染。它的平铺列表 + 搜索保持现状。

## 7. 使用记录（本地持久化）

- key：`rpa:action-usage`，value：`{ [action_id]: { count: number, lastAt: number } }`；
- 触发点：拖拽叶子节点到画布成功时、`ActionPickerDialog` 确认选择时，调用 `recordActionUsage(id)`；
- 容量：最多保留 200 条，超限按 `lastAt` 淘汰最旧；
- 读失败（JSON 损坏 / 隐私模式）静默降级为空记录，**不得阻塞面板渲染**；
- 清空入口：搜索框右侧一个「清空常用」文字按钮（仅在存在记录时显示）。

| 文件 | 问题 | 处理 |
|---|---|---|
| `src/utils/rpa/actionTypeIcon.ts` | `ACTION_TYPE_ICONS` 只有 19 项，缺 `press` / `wait_for_response` / `element_state` / `select_option` / `wait_for_url` / `get_text` / `get_window` / `fetch_external_data` / `mark_resource_result` / `random_pick` / `print` / `shuffle_list` / `sort_list` / `bili_reserve` / `pick_line` / `notify` / `open_page` / `close_page` / `parallel` | 按「交互 / 导航 / 等待 / 数据 / 控制 / 业务 / 媒体」补全，确保 31 个动作都有图标 |
| `ToolboxPanel.vue` `actionTitleMap` | 同样缺新动作，缺失时显示原始 `action_id` | 收敛到 `actionCategory.ts` 导出的 `ACTION_DISPLAY_NAME`（31 项），组件只引用不重复维护 |

> 注意：`src/utils/rpa/actionIcon.ts` 的 `getActionIconCategory*` 是**图标素材目录分类**
> （FGO头像 / Saber脸 / 指令纹章 / 礼装），与本文档的「动作分类」是两个概念，不要混用。

## 9. 验收标准

1. 「基础操作」tab 折叠状态下可一屏看到 7 个分类，展开任一分类能看到该分类下全部动作，7 类动作数合计 = 31（不含 `composite` 时 30）；
2. 输入 `wait` → 命中 `wait` / `wait_for_url` / `wait_for_response`，`wait` 排第一；
3. 输入 `导航` → 命中 `navigate` / `new_page` / `open_page` / `close_page` / `wait_for_url` 所在分类；
4. 输入不存在的词 → 显示空态，不出现空分类标题；
5. 拖拽任一动作到画布，生成的步骤参数表单与改造前一致（`DroppedItem` 无变化）；
6. 分类节点不可拖拽、不可作为步骤被投放；
7. 31 个动作在无图库素材时都能拿到 Element Plus 图标（不出现问号）；
8. `actionCategory.ts` 纯函数单测覆盖：分类映射完备性、打分排序、空查询、空结果、最近使用加成。

## 10. 非目标

- 不改后端 `ActionMetadataResponse`，不新增 `category` 字段；
- 不做「自定义动作」的分类（沿用现有 tags 过滤）；
- 不做拼音输入匹配（不引入 pinyin 依赖）；
- 不改参数表单生成逻辑（`ActionParamsForm.vue` 已是 schema 驱动，本次不动）；
- 不改步骤数据结构（`DroppedItem` 不加 `on_error` / 步骤级 `retry`）。
