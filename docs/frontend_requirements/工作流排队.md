# 工作流排队（前端需求）

## 背景

同一浏览器允许多个工作流排队执行（FIFO）。后端新增运行状态 `queued` 与字段 `queue_position`。

## 1. 状态展示

运行状态多一个值：

| status | 展示文案 | 颜色建议 |
| --- | --- | --- |
| `queued` | 排队中 | 次要色（info / 灰蓝） |
| `running` | 执行中 | 主色 |
| `success` | 成功 | 成功色 |
| `failed` | 失败 | 危险色 |
| `interrupted` | 已中断 | 警告色 |
| `cancelled` | 已取消 | 次要色 |

- 运行列表、运行详情、浏览器详情里的「关联工作流运行」都要支持；
- 不能把 `queued` 当未知状态渲染成默认灰或报错。

## 2. 排队位置

`queue_position`（int，1 基）：

- `> 0`：在排队，第 N 位（建议展示「排队中 · 第 N 位」）；
- `0`：未排队（正在执行或已结束）。

出现位置：

- `POST /workflows/run` 返回体（手动运行后可直接提示「已加入队列，第 N 位」）；
- `POST /workflows/runs/get`（详情）；
- `POST /workflows/runs`（列表项）。

## 3. 交互

- **停止**：运行详情/列表的「停止」按钮对 `queued` 同样可用，调用
  `POST /workflows/runs/stop` 即取消排队（后端直接出队并标 `cancelled`）；
- **进度条**：`queued` 阶段没有进度，进度条应显示 0% 或隐藏，不要显示「执行中」的动画；
- **刷新**：`queued` 状态会随前序运行结束自动转 `running`，建议沿用现有轮询/SSE 刷新机制，无需单独接口；
- **提示**：手动运行返回 `queued` 时给出「该浏览器正在执行其他工作流，已加入队列（第 N 位）」的提示，而不是报错。

## 4. 不需要前端做的事

- 不需要前端实现排队逻辑（后端队列）；
- 不需要新增接口；
- 不需要处理多实例（单实例部署）。
