# 动作 / 工作流「分享」（前端需求）

> 后端导出接口已存在（`custom-actions/export`、`workflows/export`），返回体与导入接口请求体完全一致。
> 本次只做前端接入，并把「导出 JSON / 导入 JSON」改写成面向用户的「分享 / 导入分享」。

## 1. 命名口径

技术上是 JSON 文件，但用户心智是「把这份配置分享给别人」，因此界面统一用「分享」：

| 位置 | 旧文案 | 新文案 |
|---|---|---|
| 动作卡片「更多」菜单 | （无） | `分享` |
| 工作流卡片「更多」菜单 | （无） | `分享` |
| 动作管理页头部按钮 | `从 JSON 导入` | `导入分享` |
| 工作流管理页头部按钮 | `从 JSON 导入` | `导入分享` |
| 弹窗标题 | （无） | `分享动作` / `分享工作流` |

界面文案中**不出现**「JSON」「导出」「导入文件」等实现词汇；只有弹窗内的复制/下载按钮保留 `JSON`（
用户实际拿到的是 `.json` 文件，需如实告知）。

## 2. 分享弹窗（动作 / 工作流共用）

组件：`src/components/rpa-browser/ShareJsonDialog.vue`

- `v-model` 控制显隐，props：`kind: 'action' | 'workflow'`、`name`、`payload`、`loading`
- 打开时机：用户点卡片「更多 → 分享」；弹窗先展示骨架屏，同时请求导出接口
- 内容区：只读 `el-input type="textarea"`，展示 `JSON.stringify(payload, null, 2)`
- 底部按钮：
  - `复制 JSON`：写入剪贴板，成功提示「分享内容已复制，可直接发送给对方」
  - `下载 JSON`：文件名 `{资源名}.json`，名称中的 `\ / : * ? " < > |` 替换为 `_`
  - `关闭`
- 说明文案：
  - `对方在「动作管理 → 导入分享」/「工作流管理 → 导入分享」中选择这份 JSON 即可导入`
  - `分享内容不包含你的账号信息与运行记录；导入后会以对方身份新建一份副本`

导出接口失败时（如资源已被删除、非本人且未公开）不弹空窗，直接关闭并展示后端 `msg`。

## 3. 导入

沿用原有文件选择逻辑（`src/utils/rpa/jsonImport.ts#pickJsonFile`），仅按钮文案改为「导入分享」；
成功提示仍为「导入成功：{名称}」，导入后刷新列表（动作页同时刷新标签）。

## 4. 样式与标识

- 无 `<style>` 块、无内联样式，全部使用 Tailwind 语义类（如 `text-gray-400`、`font-mono`）
- 功能级 class：`share-json-dialog__body` / `__meta` / `__name` / `__hint` / `__loading` /
  `__preview` / `__tip` / `__actions`，按钮入口 `action-toolbar__import`、`workflow-toolbar__import`

## 5. 验收

1. 动作卡片「更多 → 分享」→ 弹窗出现，可复制、可下载；下载的 `.json` 在另一账号「导入分享」后能还原动作（新 `action_id`）。
2. 工作流卡片「更多 → 分享」同上，导入后关联动作需已存在，否则后端报错并按后端 `msg` 提示。
3. 导出失败（无权限 / 已删除）时弹窗自动关闭并提示错误，不残留骨架屏。
4. 弹窗打开过程中慢网络下显示骨架屏，按钮置灰不可点。
