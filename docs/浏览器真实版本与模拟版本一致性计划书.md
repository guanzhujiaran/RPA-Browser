# 浏览器真实版本与模拟版本一致性计划书（v1）

> 状态：已确认方案（2026-11-25），本计划书为该改动的唯一依据。
> 关联：`app/utils/consts/browser_exe_info/browser_exec_info.json`、`docs/frontend_requirements/浏览器版本选择与校验.md`

## 1. 结论（回答三个问题）

### 1.1 随机的浏览器版本必须和 `browser_exec_info` 一致

`browser_exec_info.json` 是本项目**唯一**的 chromium 二进制清单：每条纹目的
`exec_name` 决定实际启动哪个 AppImage，`full_version` 是该二进制的真实版本。

随机指纹的版本（`--fingerprint-brand-version` / `navigator.userAgentData`）是**模拟值**，
一旦和真实二进制版本不一致，站点侧可同时读到「UA 声称的版本」「UA-CH 声称的版本」和
「真实内核行为」，属于高风险穿帮点（大版本不同尤其明显）。

**结论：必须一致，且以「先选真实二进制，再据它生成模拟版本 + UA」的顺序实现。**

现状的三个不一致口子：

1. `browser_exec_info_utils.get_exec_info()` 用 UA 字符串**全等**反查二进制，查不到时
   **静默回落第一条**（139.0.7258.154），且无日志；
2. 指纹生成用 `browserforge` 的 `uaFullVersion`（实测 `139.0.7258.139`），
   与 JSON 的 `139.0.7258.154` **patch 号不同**；
3. `botright.get_browser_engine()` 对 `execute_path` 分支**写死** `version="139.0.7258.154"`，
   装 142/144/148/150 也报 139。

### 1.2 模拟版本与真实版本需要分开存储

两者语义不同，必须分开存：

| 字段 | 语义 | 来源 | 用途 |
|---|---|---|---|
| `fingerprint_real_version`（新增） | **真实版本**：磁盘上 chromium 二进制的版本 | `browser_exec_info.json` 的 `full_version`，**只能从清单里选** | 选 `exec_name` / `exec_path`、安装校验、审计 |
| `fingerprint_brand_version`（已有） | **模拟版本**：下发给浏览器的 `--fingerprint-brand-version`，即 `navigator.userAgentData` 报告值 | 默认取真实版本；**允许在同一主版本内改成别的 patch**（见 §1.4） | 指纹注入 |

约束是「**主版本必须一致，patch 可不同**」：

- 真实版本是「选二进制」的**权威键**，不再依赖 UA 字符串匹配；
- 模拟版本是可被注入的展示值：不改 major 时内核特性集、TLS/JA3 都不变，站点无从校验 patch，
  改成同 major 的其他 patch 是安全的，也能避免整批浏览器报同一个 patch 形成聚类特征；
- 但**跨 major** 一律拒绝：缺 API / TLS 指纹 / 报错文案都会暴露真实内核区间（§3.3）；
- 分开存才能**检出**漂移（历史数据已存在 `139.0.7258.139` vs `139.0.7258.154` 的漂移）。

### 1.4 为什么模拟版本可以改、但只能改 patch

`--fingerprint-brand-version` 只影响声明层（UA-CH 的 `brands[].version` = major、
`Full-Version-List` / `getHighEntropyValues().uaFullVersion` = 完整四段号）；
UA 字符串由 `--user-agent` 决定且必须是 `major.0.0.0` 的缩减格式。

因此：

- 只改 patch（如真实 150.0.7871.186 → 报告 150.0.7871.124）：所有可观测通道仍是「150」，
  与内核行为一致，安全；
- 改 major（如真实 144 → 报告 150）：UA 主版本、UA-CH 主版本要一起改，而内核缺 145~150 的 API、
  TLS/JA3 也仍是 144 的，必被识破。

### 1.3 前端从服务端读配置，前后端都校验

- 后端新增「可选真实版本清单」接口（数据源 = `browser_exec_info.json`）：
  返回 `full_version` / `major_version` / `browser_ua` / `exec_name` / `is_installed`；
- 前端表单的「真实版本」改为**下拉**，选项来自上述接口；「模拟版本」可编辑但**主版本锁死**
  （默认跟随真实版本，改了 major 直接提示）；
- 后端在 upsert / update 处做**白名单校验**：真实版本必须在清单内；模拟版本必须是完整四段号
  且与真实版本主版本一致，否则 400；
- 生成/更新时由后端统一把 `patchright_browser_ua`、`fingerprint_brand_version`、
  `fingerprint_real_version`、`patchright_fingerprint_dict.navigator` 四者同步：
  UA / 二进制取真实版本，UA-CH 的完整版本号取模拟版本，避免前端拼装出不一致组合。

## 2. 数据模型

### 2.1 `userbrowserinfo` 新增列

```python
fingerprint_real_version: str | None = Field(
    None, nullable=True,
    description="真实浏览器版本（来自 browser_exec_info.json），决定实际启动的 chromium 二进制",
)
```

迁移：`alembic/versions/20261125_fingerprint_real_version.py`

- `upgrade`：加列（`sa.String(64)`，可空）；
- 存量回填：按 `patchright_browser_ua` 匹配清单，一并把 `fingerprint_brand_version`
  修正为清单 `full_version`（修掉 `139.0.7258.139` vs `139.0.7258.154` 的 patch 漂移）；
- `downgrade`：删列。

### 2.2 该字段不参与 chromium 命令行

`fp_2_args_list()` 会遍历所有非空字段拼 `--xxx`，必须在 `NON_CLI_ARG_KEYS`
中加入 `fingerprint_real_version`，否则会下发一个不存在的开关。

## 3. 运行时

### 3.1 启动选二进制

`BaseUndetectedPlaywright.launch_browser_span()` 改为：

```python
exec_info = await browser_exec_info_helper.get_exec_info(
    real_version=fingerprint_params.fingerprint_real_version,
    ua=fingerprint_params.patchright_browser_ua,   # 旧数据兜底
)
executable_path = await ensure_appimage_extracted(exec_info)
Botright(..., execute_path=executable_path, browser_version=exec_info.full_version)
```

`get_exec_info` 的匹配顺序：

1. `real_version` 精确匹配 → 命中即返回；
2. 未命中：用 `ua` 全等匹配（兼容未回填的历史行），命中打 INFO 日志；
3. 仍未命中：回落清单第一条，**打 WARNING 并带上 version/ua**，不再静默。

### 3.2 Botright 不再写死版本

`Botright.__init__ / __ainit__` 新增 `browser_version: str | None = None`，
透传给 `get_browser_engine(execute_path, version)`；未传时保留原常量作为兜底。

## 3.3 上游 fingerprint-chromium 的版本机制（2026-11-25 核对）

来源：`adryfish/fingerprint-chromium` README（中/英）与多个镜像的参数表。

| 参数 | 作用 | 取值 |
|---|---|---|
| `--fingerprint-brand` | 指定 **UA 与 UA-CH 的品牌** | `Chrome` / `Edge` / `Opera` / `Vivaldi`（默认 Chrome） |
| `--fingerprint-brand-version` | 指定该品牌的版本号 | 四个内置品牌各有默认值，**允许传自定义版本**（README 原文 "custom versions can also be passed"） |
| `--user-agent` | Chromium 原生开关，改 `navigator.userAgent` 与 `User-Agent` 头 | 缩减格式：`Chrome/<major>.0.0.0` |

结论：

1. **内核不校验版本是否等于自身内核版本**，也不存在版本白名单——传什么就报什么；
   因此「能不能模拟不同版本」是工程自洽问题，不是开关限制问题；
2. 版本号只影响「声明层」：UA-CH 的 `brands[].version`（主版本）、
   `Full-Version-List` / `getHighEntropyValues().uaFullVersion`（完整四段号）；
   真实内核的 TLS 指纹、JS 特性集、WebGL/字体度量等仍来自二进制本身；
3. 因此**向上模拟大版本必然穿帮**（缺 API），向下模拟旧版本也只是部分可隐藏；
   官方推荐的自洽区间是「同 major，允许 patch 微调」；
4. UA 字符串必须保持缩减格式（`major.0.0.0`），完整四段号只出现在高熵通道——
   我们的清单 UA 已经是这个格式（`Chrome/150.0.0.0`），无需手工拼装。

### 3.4 由此发现的两个既有缺陷（本次一并修）

1. **品牌开关名写错**：模型里 `fingerprint_browser` 的 alias 是 `--fingerprint-browser`，
   而上游文档与所有镜像均为 `--fingerprint-brand`。Chromium 会静默忽略未知开关，
   等于品牌从未下发（UA-CH 退回默认品牌），`--fingerprint-brand-version` 也就失去了归属。
   → alias 改为 `--fingerprint-brand`。
2. **品牌取值大小写**：库里 ENUM 值是 `chrome`，而上游认的是 `Chrome`（列表首字母大写）。
   → 在 `fp_2_args_list()` 里做「ENUM 值 → 命令行字面量」映射，DB 值不变。

> 说明：`--user-agent` 与 `--fingerprint-brand[-version]` 是「投影 + 声明」两层，
> 只要 major 对齐就不会互相矛盾；本次的「真实版本 = 模拟版本」策略正好保证这一点。

### 3.5 种子（`--fingerprint`）与显式参数的叠加效应

上游语义：`--fingerprint=<seed>` 启用大部分伪装并派生一组值；显式参数（`--fingerprint-hardware-concurrency`
/ `--fingerprint-gpu-*` / `--fingerprint-platform*` / `--fingerprint-brand*`）是**覆盖**，内核不做一致性校验。
所以问题不在「报错」，而在「同一表面被两个来源写入，谁赢随 surface / 内核版本变化」。

原则：**每个表面只保留一个写入源**。

| 表面 | 唯一写入源 | 现状 |
|---|---|---|
| UA / UA-CH 品牌与版本 | CDP override（清单 UA + 模拟版本）+ `--fingerprint-brand[-version]` 同值 | 已对齐（§3.3/§4） |
| canvas / audio / clientRects / fonts | `--fingerprint` 种子 | 修掉了 `--fingerprinting-canvas-image-data-noise` 的二次噪音 |
| `navigator.hardwareConcurrency` | `--fingerprint-hardware-concurrency`（显式） | 保留：种子的值不可控，必须显式传才能与库内一致 |
| GPU vendor/renderer | ≤143 走 `--fingerprint-gpu-*`；≥144 只能由种子决定 | **保留字段，UI 标注仅旧版本生效**（用户 2026-11-26 决策） |
| 语言 | 指纹 `lang` / `languages`（context locale + CDP acceptLanguage 同值） | 修掉了硬编码 `en-US` |
| 时区 | Playwright `timezone_id`（代理 IP）优先于 `--timezone` | 暂不处理，见下 |

已修复的两个双重写入：

1. **canvas 双噪声**：`botright/botright.py` 曾对 chromium 追加
   `--fingerprinting-canvas-image-data-noise`，与种子的 canvas 伪装叠加，导致同会话内
   `getImageData` 读数不稳定（「canvas 噪音」特征）。已移除，chromium 交给种子。
2. **语言双写**：`botright/playwright_mock/browser.py` 的 context `locale` 与
   `playwright_mock/page.py` 的 CDP `acceptLanguage` 都写死 `en-US`，会覆盖
   `--lang=zh-CN` / `--accept-lang`。已改为跟随指纹的 `language` / `languages`。
   同时修掉 browserforge 的 `languages` 脏数据：它是从 `Accept-Language` 头按逗号拆出来的，
   带前导空格（`['zh-CN', ' zh', ' en', ...]`），生成时统一 `strip()`，
   否则 `--accept-lang` 与落库的 `navigator.languages` 都是非法语言项。

GPU 覆盖的口径（决策）：

- 字段与命令行参数**都保留**（≤143 真实生效；≥144 被内核静默忽略，无副作用）；
- `GPU_OVERRIDE_LAST_SUPPORTED_MAJOR = 143` 定义在
  `app/models/core/browser/fingerprint.py`，字段 description 与前端常量（
  `src/models/rpa_browser/fingerprint.ts`）共用同一口径；
- 表单与指纹详情在 ≥144 时提示「这两项不会生效，实际 GPU 由指纹种子决定」。

时区（未改）：`--timezone` 与 Playwright `timezone_id=proxy.timezone` 双写，
CDP 覆盖优先。按代理 IP 收敛时区本身是合理的（与出口 IP 一致），
但库内 `timezone` 记录会与实际不符，后续如需一致应改为「落库存实际生效值」。

## 4. 生成与校验

### 4.1 随机生成（`gen_from_browserforge_fingerprint`）

1. 先确定条目：请求指定了 `fingerprint_real_version` 就用它，否则从清单**随机**挑一条；
2. 只用该条目的 `browser_ua` 作为 UA 池生成指纹（保证 browserforge 输出与该 UA 自洽）；
3. **强制覆盖** `navigator.userAgentData.uaFullVersion` / `fullVersionList` 为该条目的
   `full_version`，并令 `fingerprint_brand_version = full_version`；
4. 落库 `fingerprint_real_version = full_version`。

### 4.2 upsert / update 校验（`app/services/RPA_browser/fingerprint/exec_version_service.py`）

```python
async def resolve_exec_info(real_version: str | None, brand_version: str | None) -> BrowserExecInfoModel | None
def apply_exec_info(
    target: BaseFingerprintBrowserInitParams,
    exec_info: BrowserExecInfoModel,
    brand_version: str | None = None,
) -> None
```

`resolve_exec_info` 规则：

| 入参 | 行为 |
|---|---|
| 两者都空 | 返回 `None`（不改版本，保持现状） |
| 只给真实版本 | 必须在清单中，命中返回 |
| 两者都给 | 真实版本必须在清单中；模拟版本必须是四段号且**主版本相等**，否则 400；patch 不同则保留用户值 |
| 只给模拟版本 | 先按完整版本匹配；不中再按**主版本号唯一匹配**；仍不中 → 400 |

`apply_exec_info` 同步：

- `fingerprint_real_version` = `full_version`（选二进制）
- `fingerprint_brand_version` = 入参 `brand_version`，未传则等于 `full_version`
- `patchright_browser_ua` = `browser_ua`（UA 主版本与两者一致）
- `patchright_fingerprint_dict.navigator` 的 `userAgent` / `userAgentData.uaFullVersion` /
  `brands[].version`（major）/ `fullVersionList[].version`（完整号）按**模拟版本**同步；
  整体**重新赋值新 dict**（JSON 列原地改不会被 SQLAlchemy 记为脏数据）

`BrowserFingerprintService.upsert_fingerprint` / `update_fingerprint` 在写库前调用上述两步；
`create_fingerprint` 由生成流程直接产出。
